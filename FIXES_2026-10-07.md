## Audit fixes — 2026-10-07 (second pass)

6. scripts/audit-release.py — **the release gate could never reach its ZIP steps.** The script scans every
   path for `BAD_PARTS` (`.git`, `.venv`, `node_modules`, `__pycache__`, `.pytest_cache`, `.mypy_cache`,
   `.ruff_cache`), but the gate invokes it as `audit-release.py "$ROOT"` *after* `npm ci` and
   `python -m compileall`, so every dependency file and bytecode cache was reported forbidden
   (~96k errors) and `set -e` aborted the gate. `names_from()` now prunes exactly the directories that
   `scripts/make-release-zip.sh` already excludes when auditing a directory tree; the ZIP audit (the
   shipped-artifact check) is untouched and still rejects forbidden entries. Verified: the repo-root
   audit passes, a crafted ZIP containing `node_modules/` is still rejected, and the real ZIP builds,
   unzips (`unzip -t`) and audits clean.
7. backend/tests/test_canonical_data_completion.py, backend/tests/test_deep_release_audit.py — two
   assertions hard-coded whitespace-free TypeScript source (`items?:CanonicalFieldValueItem[]`,
   `map:map.slice(left,rightTrimmed)`) and failed against the correctly prettier-formatted source
   (2 failing tests). They now compare against whitespace-collapsed source: the semantic contract is
   still asserted, but formatter changes can no longer break it.
8. word-extension/src/services/authService.ts — empty `catch {}` (`no-empty`) around the
   office-exchange error-body parse; now documents why it falls back to the generic message.
9. word-extension/webpack.config.js — three proxy hooks declared a `res` parameter they never used
   (`@typescript-eslint/no-unused-vars`); renamed to `_res`, the eslint config's documented `^_`
   convention.
10. word-extension/src/services/word/eventService.ts — the `runWordOperation` callback named its
    request context `ctx`, which the office-addins rules do not recognize as a sync boundary
    (`isContextSyncIdentifier` requires the name `context`), producing 6 false `call-sync-after-load`
    / `call-sync-before-read` errors. Renamed to `context`, matching the rest of the codebase.
    Behaviour unchanged.
11. word-extension/src/services/documentExtraction.ts — three `controls.items.length` reads were
    missing the justified `load-object-before-read` suppression already present at the 11 sibling
    sites (`items` is loaded via `load("items")` + sync; the rule models `items.length` as a separate
    `items/length` property that no load string can satisfy).
12. word-extension/src/services/wordDraftRenderer.ts, word-extension/src/services/word/reconciliationService.ts
    — justified suppressions for two genuine plugin false positives: `ClientResult.value` returned by
    `getOoxml()` (a ClientResult has no loadable properties; its value is populated by the sync) and
    the duck-typed `range.contentControls` navigation path in the best-effort structural check. No
    behaviour change; each carries an explanatory comment.
13. word-extension/** — `eslint --fix` applied the 41 outstanding `prettier/prettier` formatting
    errors. Lint is now **0 errors**.
14. scripts/make-release-zip.sh + scripts/audit-release.py — **no dev could pass the release gate, and a
    local `.env` could ship.** `backend/SETUP.md` tells every developer to run
    `cp .env.example .env`, and `scripts/release-gate.sh` audits the source tree *before* packaging, so
    `audit-release.py` rejected the developer's own `backend/.env` (`forbidden path: backend/.env`,
    exit 1) and `set -e` aborted the gate before the ZIP step — the same failure mode as item 6.
    Worse, `make-release-zip.sh` did not exclude `.env`, so running the packager on its own produced a
    release archive containing `DATABASE_URL` credentials, `AUTH_HMAC_SECRET` and
    `OBJECT_STORE_ENCRYPTION_KEY`.
    - The packager now excludes `.env` and `.env.local` at every depth (`.env.example` still ships).
    - `walk_source()` skips `BAD_NAMES` for the source-tree audit, with the same rationale as the
      `BAD_PARTS` pruning: those files are excluded from the archive, so they cannot fail the gate.
    - `.env.local` was added to `BAD_NAMES`, so the **archive** audit (unchanged in strictness) now also
      rejects `.env.local` if one ever reaches an artifact.
