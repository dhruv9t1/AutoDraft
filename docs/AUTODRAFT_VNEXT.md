# AutoDraft reliability and drafting upgrade

AutoDraft now has exactly two identification modes: LEGAL and GENERAL. LEGAL unions deterministic legal extraction, labelled-value recovery, semantic extraction and a separate coverage audit. GENERAL scans the complete document without subtype routing. Word extraction now includes body text plus missing table-cell text, section headers/footers and document-level content-control text.

No arbitrary-document system can truthfully promise mathematical 100% semantic extraction. The implementation instead targets maximum legal recall and fail-visible review: exact source anchoring, multiple independent detection passes, coverage warnings, manual add-variable support, and a pre-completion verifier.

Before Complete Drafting the add-in re-reads the final document and checks empty fields, unresolved placeholders, stale original values, values absent from the document, suspicious duplicate values and a second semantic legal consistency audit. Blockers stop completion; warnings require review.

The AI Drafting Workspace accepts matter facts, produces drafting text and questions/sections/assumptions, inserts drafts into Word, and exposes similar-case research only as an explicit opt-in. The model is prohibited from inventing precedents and may cite only retrieved authorities supplied to it.

Dynamic client intake forms can be generated by matter type, shared through a tokenized public link, submitted to PostgreSQL, reloaded by the lawyer, and mapped to Word content controls using each question's mapsTo field.

Deployment: backend startup now applies migrations. Public intake links require the backend base URL to be client-reachable. Lawyer APIs remain behind the existing API authentication configuration.
