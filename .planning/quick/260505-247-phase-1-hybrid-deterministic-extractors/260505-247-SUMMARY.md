# Quick Task 260505-247: Phase 1 Hybrid Deterministic Extractors

## What Was Implemented

Phase 1 of `docs/DETERMINISM_AND_ACCURACY_TRACK.md`: regex-based deterministic extractors for
the eight categories with strict format, integrated into both the batch and streaming
variable-identification pipelines, with extractor-wins semantics on `original_text` overlap.

### Commits

**Commit `b239bc2` — extractors module + 8 category extractors + 56 unit tests:**

- New `backend/src/extractors/` module with `Extractor` trait, `Extraction` value type, and
  a public `extract_all(document) -> Vec<Extraction>` registry that runs every category and
  returns hits sorted by byte position.
- One source file per category: `pin`, `gstin`, `ifsc`, `mobile`, `email`, `date`,
  `cheque_account`, `section_act`. Each holds its compiled regex (via stdlib `LazyLock`) and
  its own `#[cfg(test)] mod tests` block with positive + negative cases.
- The GSTIN sketch in the doc table listed `\d{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z\d]Z[A-Z\d]` and
  labelled it "15-char", but that pattern matches 16 characters — a typo. The extractor
  implements the real 15-char canonical form `\d{2}[A-Z]{5}\d{4}[A-Z]\dZ[A-Z\d]`. The doc has
  been updated.
- Wired into both `src/lib.rs` (`pub mod extractors`) and `src/main.rs` (`mod extractors`)
  so the same module is reachable from integration tests and the binary.

**Commit `13ee7b2` — wire extractors into `identify_variables` (batch + streaming):**

- New `chunk_document_with_offsets` returns `(chunk_text, byte_offset)` pairs; existing
  `chunk_document` is now a thin wrapper.
- New `extractor_hits_to_variables` converts `Extraction` → `Variable` (confidence_score=1.0,
  id=None, current_value=None, position = byte offset).
- New `anchors_in_chunk` filters extractor hits to a chunk's byte window so each chunk's
  prompt only sees anchors whose `original_text` actually lives in that chunk.
- New `build_user_prompt_with_anchors` adds an `<anchors>` section listing
  `- {category}: {original_text}` lines; the system prompt's HARD RULES still apply.
- `process_chunk` consolidated into `process_chunk_with_anchors`; passing `&[]` disables the
  anchor section and reproduces the old behavior verbatim.
- `identify_variables` (batch path): extracts → anchors per chunk → joins → prepends
  extractor variables → existing `filter_list_markers → validate_variables →
  dedup_by_original_text → dedup_substring_overlap → sort_by_position` chain.
  `dedup_by_original_text` keeps the FIRST occurrence so prepending = "extractor wins on
  equal `original_text`".
- `identify_variables_streaming` (SSE path): runs extractors once, emits a synthetic
  `ChunkDone { chunk_index = total, total_chunks = total + 1, variables = anchor_vars }`
  event before any LLM chunk lands, and seeds `seen_keys` with anchor original_texts so the
  existing per-chunk substring-overlap dedup drops LLM hits that cover the same physical
  span.

**Commit `ffe7684` — integration test + merge helper extraction:**

- Refactor: `merge_extractor_and_llm(extractor_vars, llm_vars, document) -> Vec<Variable>`
  pulled out of `identify_variables` as a public method so the merge sequence is
  independently testable and reusable. `merge_anchors_for_test` wraps the full path
  (extract_all + merge) for tests.
- New `backend/tests/extractor_merge.rs` with 5 tests covering:
  - All deterministic extractor hits surface even when the LLM returned nothing.
  - Unique LLM-only variables (no overlap) are preserved.
  - On equal `original_text`, exactly one row survives with `confidence_score=1.0` (the
    extractor's signature) and the extractor's variable name.
  - LLM strict-substring of an extractor hit gets dropped by substring-overlap dedup.
  - Result is sorted by position.
- `cargo test`: 57 lib + 57 bin + 2 chunking + 5 extractor_merge + 1 ignored Ollama snapshot —
  all green.

**Final docs commit:** ticks Phase 1 status checkboxes in `DETERMINISM_AND_ACCURACY_TRACK.md`,
flags the 20-doc smoke-set recall measurement as deferred (operational, not implementation),
and corrects the GSTIN sketch typo.

## Tests

- **Unit tests** (in each extractor file): 56 tests across the 8 categories. Positive +
  negative cases, including spaced variants for PIN/GSTIN/Mobile, prefix preference for
  Mobile, label parsing for Cheque/Account, and 4 act-form variants for Section + Act.
- **Module-level tests** (in `extractors::tests`): position-sorted invariant, empty-document
  invariant, confidence-score invariant.
- **Integration test** (`backend/tests/extractor_merge.rs`): 5 tests on the merge path with a
  synthetic document and synthetic LLM-style variable list.
- **Existing tests** (chunking_determinism.rs): still pass — chunking semantics preserved.
