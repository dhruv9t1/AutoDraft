<objective>
Implement Phase 1 (hybrid deterministic extractors) from `docs/DETERMINISM_AND_ACCURACY_TRACK.md`
lines 51–76 in the Rust backend.

Stop relying on the LLM for the eight categories listed in the doc's table that have a strict
format (PIN, GSTIN, IFSC, mobile, email, date, cheque/account, Section + Act). Run regex-based
extractors on the full document **before** chunked LLM extraction; pass the hits as a
do-not-miss anchor list in the user prompt; after the LLM returns, union both sets and let the
deterministic extractor win on `original_text` overlap.

Output:
- New `backend/src/extractors/` module with `Extractor` trait, `Extraction` value type,
  `extract_all` registry, and one source file per category.
- Each extractor has its own unit tests (positive + negative cases) covering at minimum the
  examples and the spaced/labelled variants called out in the doc table.
- `OllamaService::identify_variables` and `OllamaService::identify_variables_streaming` both
  pre-compute the anchor list, embed it in the user prompt via a new
  `build_user_prompt_with_anchors`, and merge extractor hits into the validated variable list
  using the existing `validate_variables`, `dedup_by_original_text`, and
  `dedup_substring_overlap` helpers.
- One integration test in `backend/tests/extractor_merge.rs` that exercises the merge path
  end-to-end with a synthetic document and a synthetic LLM-style variable list.
- `docs/DETERMINISM_AND_ACCURACY_TRACK.md` Phase 1 task boxes ticked, with the 20-doc
  smoke-set recall measurement explicitly flagged as deferred (operational verification).
</objective>

Modify:
- `backend/src/lib.rs` — `pub mod extractors;`

`mod.rs` exposes:
```rust
pub struct Extraction {
    pub category: &'static str,
    pub variable_name: String,
    pub original_text: String,
    pub position: usize,
    pub confidence_score: f64,
}

pub trait Extractor: Send + Sync {
    fn category(&self) -> &'static str;
    fn extract(&self, document: &str) -> Vec<Extraction>;
}

pub fn extract_all(document: &str) -> Vec<Extraction> { ... }
```

Each extractor returns hits with byte offsets (so `position: i64` is consistent with the rest
of the codebase) and `confidence_score = 1.0`.

Patterns are taken verbatim from the doc table:
- PIN: `\b\d{6}\b` plus the spaced variant `\b\d{2}\s\d{2}\s\d{2}\b`.
- GSTIN: `\d{2}[A-Z]{5}\d{4}[A-Z]\d[A-Z\d]Z[A-Z\d]` (15 chars). Spaced-letter variant
  is handled by removing single-space separators between alpha chars before validating.
- IFSC: `\b[A-Z]{4}0[A-Z0-9]{6}\b`.
- Mobile: `\b[6-9]\d{9}\b` and `\+91\s?[6-9]\d{9}\b`.
- Email: RFC-lite `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}`.
- Date: `\b\d{1,2}[/-]\d{1,2}[/-]\d{2,4}\b` (DD/MM/YYYY first per doc).
- Cheque/Account: label-anchored
  `(Cheque\s*No\.?|A/c\s*No\.?|Account\s*No\.?)\s*[:\-]?\s*[\d\s]+`.
- Section + Act:
  `Section\s+\d+(?:\([a-z]\))?\s+of\s+(?:The\s+)?[A-Z][\w\s,]+(?:Act|Code|Ordinance)(?:,?\s*\d{4})?`.

Each extractor source file holds the regex (compiled lazily via `once_cell::sync::Lazy` if the
crate is already a dependency, otherwise a function-local `Regex::new`) plus a `#[cfg(test)]`
module covering positive and negative cases.

Verify: `cargo test -p word-addin-backend extractors` runs and passes.

**Task 2 — Integrate extractors into `identify_variables` and `identify_variables_streaming`**

Modify `backend/src/ollama.rs`:

1. New helper `Self::extractor_hits_to_variables(hits) -> Vec<Variable>` that converts
   `Extraction` into the `Variable` model used by the rest of the pipeline (sets
   `id = None`, `current_value = None`, `confidence_score = Some(1.0)`,
   `position = byte offset`).

2. New helper `Self::build_user_prompt_with_anchors(document_content, anchors)` that wraps
   the existing user prompt with a `<anchors>` section listing extractor hits the LLM should
   not miss but does not need to re-emit. The anchor list is rendered as
   `- {category}: {original_text}` lines. Keep `<document>` tag in sync with the system
   prompt's HARD RULES.

3. `process_chunk` accepts an optional anchors slice and uses
   `build_user_prompt_with_anchors` when non-empty; otherwise falls back to the existing
   `build_user_prompt`. The chunk-level anchor list is filtered to anchors whose byte
   `position` falls inside the chunk's offset window so the LLM only sees relevant ones.

4. `identify_variables` (batch path):
   - Call `extractors::extract_all` on the full document.
   - Convert hits to `Variable`s.
   - Pass anchors into each `process_chunk` call.
   - After all chunk results join, **prepend** the deterministic-extractor variables to
     `all_variables` before the existing `filter_list_markers → validate_variables →
     dedup_by_original_text → dedup_substring_overlap` chain. `dedup_by_original_text` keeps
     the first occurrence, so prepending = "extractor wins on equal original_text".

5. `identify_variables_streaming`:
   - Run extractors on the full document at the start.
   - Pass anchors to each `process_chunk` call.
   - After all chunks complete, prepend the extractor variables before the final dedup pass.
     Stream the extractor hits as a synthetic `ChunkDone` event with `chunk_index = total`
     and `total_chunks = total + 1` so the frontend pipeline writes them into the document
     alongside LLM results. Update `seen_keys` so the existing per-chunk dedup correctly
     drops LLM substring overlaps.

Verify: `cargo build` passes; existing `validate_variables` / dedup helpers unchanged.
